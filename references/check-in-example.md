# 从「让活动签到省事一点」到一份可交接的计划

**用户**　让活动签到省事一点，帮我出个计划。

**助手**　你最希望省掉哪一步的时间？可以选一项，也可以说一个最近发生的例子。

- A　现场找人。让工作人员更快找到名字并标记到场，需要调整现场操作。
- B　活动后对账。沿用现场流程，从报名名单和签到记录里整理出席结果，需要能拿到两份记录。
- C　参与者排队。让大家自助签到，需要准备参与者能用的入口。

**用户**　B。这次只要一份能交给同事的制作计划。最终要做的是运营能反复粘贴两张表的 Excel 模板。报名表有唯一的报名号和姓名，扫码明细只有报名号。编号当文本，007 和 7 是两人。扫两次只算一人，未到的要列出来，陌生号单列。

## 交给执行者的计划

为活动运营制作一份可复用的 Excel 签到对账模板。运营粘贴本场报名表和扫码明细后，应能看到每位报名者的到场状态、已到的报名人数和单列的陌生号。用文本报名号精确匹配，重复扫码只计一次。

| 任务 | 输入和交付物 | 可以交接的条件 |
| --- | --- | --- |
| 制作模板 | 按两张来源表的已知列制作粘贴区和结果区 | 运营可以替换本场输入。报名号保留前导零，结果覆盖已到、未到及陌生号。 |
| 独立准备验收样例 | 在模板外准备两场活动，每场一张报名表和两轮扫码明细 | 样例可以直接粘贴，预期由报名和扫码原始记录逐条推出。 |
| 用模板复核 | 在同一份模板里依次粘贴下表四轮输入，跨场时替换两张表 | 逐轮核对每人状态、已到人数和陌生号。每轮输入及重算结果可用于复核。 |

单人按表格顺序执行。多人赶工时，前两项可同时开始，一人写模板，另一人写独立样例。两份产物就绪就交给模板制作者跑同一套验收。

本轮可用 Excel 公式计算状态。执行者换用 Excel 查询功能，只要运营仍可按约定粘贴数据并得到正确结果，同样可以通过。验收时可直接指出哪些人的状态错了，或哪一轮总数算错了。

| 从运营入口做的操作 | 必须观察到的结果 |
| --- | --- |
| 报名号为 `007`、`7`、`012`，分别填入三个不同姓名。依次粘贴扫码号 `007`、`007`、`099`。 | 已到人数为 1，只有 `007` 已到。`7` 和 `012` 都未到。`099` 出现在陌生号区。 |
| 保留报名表，用只有一条 `7` 的新明细替换扫码区原有记录。 | 已到人数仍为 1，这次只有 `7` 已到。`007` 和 `012` 未到，陌生号区为空。 |
| 在刚用过的模板中，用第二场记录替换两张表。报名号为 `042`、`42`，扫码号为 `42`、`42`、`042`、`0042`。 | 已到人数为 2，`042` 和 `42` 均已到，未到名单为空。陌生号区只有 `0042`，结果区只含本场记录。 |
| 保留第二场报名表，用只有一条 `0042` 的新明细替换整个扫码区。 | 已到人数为 0，`042` 和 `42` 都未到，陌生号区只有 `0042`。 |

先用能完成前两轮粘贴的最小模板判断对账逻辑。前两轮已到人数同为 1，但到场者换了人。第二轮若仍显示 `007` 已到，人数正确也应退回。后两轮的正确人数从 2 变为 0，可以查出人数始终显示为 1 的模板。

再看一次只复核的请求。制作者在旧计划里照演示选了“已到”，新版写“已签到”。制作人只核过样本中每个人的状态，运营尚未试用。另有工具导入用途，读取规则和整体启用条件均未知。可以这样反馈。

> 样本中每个人的状态都与扫码记录一致，这项核对通过。运营能否用新版完成整场对账仍待试用，工具能否导入仍待试导。新措辞偏离旧计划中的演示写法。整体启用条件待确认。

如果后来运营用新版完成对账，工具实测只接受“已到”，并且交付约定明确要求两种用途同时可用，就更新为“运营对账通过，工具导入不通过，正式启用受阻”。导致整体受阻的依据是导入实测与交付约定。

如果运营反馈“换了扫码明细，已到的还是上次那个人”，执行者应在出现问题的版本上复现前两轮替换，用相同输入检查修订版，并核对未到名单和陌生号区是否也残留旧记录。若表中数据已用于调校，再用未参与修订的一场数据复核跨场替换。

反馈时注明实际试用的模板版本和粘贴方式。如果只试过前两轮且均通过，就报告同场更换到场者的实测结果。跨场复用和无人到场仍待验证，用后两轮补验后更新结论。
