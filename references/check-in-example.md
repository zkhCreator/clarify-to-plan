# 从「让活动签到省事一点」到一份可交接的计划

**用户**　让活动签到省事一点，帮我出个计划。

**助手**　你最希望省掉哪一步的时间？可以选一项，也可以说一个最近发生的例子。

- A　现场找人。让工作人员更快找到名字并标记到场，需要调整现场操作。
- B　活动后对账。沿用现场流程，从报名名单和签到记录里整理出席结果，需要能拿到两份记录。
- C　参与者排队。让大家自助签到，需要准备参与者能用的入口。

**用户**　B。运营现在用 Excel。报名表有唯一的报名号和姓名，扫码明细只有报名号。给我一个能反复粘贴两张表的模板。编号当文本，007 和 7 是两人。扫两次只算一人，未到的要列出来，陌生号单列。

## 交给执行者的计划

为活动运营制作一份可复用的 Excel 签到对账模板。运营粘贴本场报名表和扫码明细后，应能看到每位报名者的到场状态、已到的报名人数和单列的陌生号。用文本报名号精确匹配，重复扫码只计一次。

| 任务 | 输入和交付物 | 可以交接的条件 |
| --- | --- | --- |
| 制作模板 | 按两张来源表的已知列制作粘贴区和结果区 | 运营可以替换本场输入。报名号保留前导零，结果覆盖已到、未到及陌生号。 |
| 独立准备验收样例 | 在模板外准备同一场的两轮扫码记录，再留一场独立记录用于复核 | 样例可以直接粘贴，预期由报名和扫码原始记录逐条推出。 |
| 用模板复核 | 制作模板的人接收样例，在同一份模板里先替换扫码明细，再跨场替换两张表 | 对照下列判据，保留每轮的输入和重算后的结果页作为证据。 |

单人按表格顺序执行。多人赶工时，前两项可同时开始，一人写模板，另一人写独立样例。两份产物就绪就交给模板制作者跑同一套验收。

| 从运营入口做的操作 | 必须观察到的结果 |
| --- | --- |
| 报名号为 `007`、`7`、`012`，分别填入三个不同姓名。依次粘贴扫码号 `007`、`007`、`099`。 | 已到人数为 1，只有 `007` 已到。`7` 和 `012` 都未到。`099` 出现在陌生号区。 |
| 保留报名表，用只有一条 `7` 的新明细替换扫码区原有记录。 | 已到人数仍为 1，这次只有 `7` 已到。`007` 和 `012` 未到，陌生号区为空。 |
| 在刚用过的模板中，用另一场记录替换两张表。例如报名号为 `042`、`42`，扫码号为 `42`、`42`、`0042`。 | 只有 `42` 已到，`042` 未到，`0042` 单列。结果区只含这一场的记录。 |

先用能完成前两轮粘贴的最小模板判断对账逻辑。两轮正确的已到人数恰好都是 1，第二轮若仍显示 `007` 已到，即使总数正确也应退回。反过来，运营约定了报名号的匹配方式，结果行的顺序由制作者选择。按姓名或按报名号排序的模板，只要逐人状态、总数和陌生号列表都正确，就能通过这项核对。

如果运营反馈“换了扫码明细，已到的还是上次那个人”，执行者应在出现问题的版本上复现前两轮替换，用相同输入检查修订版，并核对未到名单和陌生号区是否也残留旧记录。最后用未参与修订的另一场数据复核跨场替换。

反馈时注明实际试用的模板版本和粘贴方式。若只验过同场替换扫码明细，跨场复用仍属待验证，应在交付前补做最后一次替换。
